## Формат экзамена

Экзамен проходит в двух форматах:

### 1. Устный формат (разговор)
- Разговор по темам, которые мы реально разрабатывали на курсе

- Уточняющие вопросы на понимание
- Ответы своими словами, без зубрёжки

### 2. Письменный формат (дистанционный)
- Часть A: объяснение концепций своими словами (3–6 предложений)
- Часть B: разбор кода — найти проблему, объяснить решение

## Структура курса и проекты

На курсе мы разрабатывали три проекта:

- **Notes** (Razor Pages) — простое приложение для заметок
- **PersonalAccount** (MVC) — кабинет студента с ролями и авторизацией
- **Marketplace** (Web API + микросервисы) — платформа покупки-продажи товаров на микросервисной архитектуре

## Особенность вашей группы: JWT вместо cookie

В отличие от некоторых других групп, в ваших проектах используется **JWT в Authorization header** для авторизации между микросервисами, а не cookie с общим ключом DataProtection.

**Где это важно:**
- **Тема 7 (авторизация на микросервисах):** токены передаются в заголовке `Authorization: Bearer <token>`, а не в cookie
- **Тема 10 (микросервисы):** все сервисы проверяют подпись JWT с одним секретным ключом, а не расшифровывают cookie

Это современный подход, чаще встречается в реальных проектах и на собеседованиях.
